# 数据与特征体系（钢铁流通场景）

> 目标：把平台已有的行为数据 + IM 数据，转化为**可解释、可审计、抗行情干扰**的意向信号。
>
> 核心判断：消费电商那套「浏览-收藏-加购-下单」漏斗特征在钢贸场景里**权重严重失真**，必须重建信号体系。

---

## 一、数据源清单与可用性评估

| 数据源 | 典型字段 | 意向价值 | 噪声来源 | 隐私敏感度 |
|---|---|---|---|---|
| 宣发物料扫码 | 物料ID、渠道（展会/仓库门牌/名片/DM单）、时间、地理位置 | **低** | 业务员代扫、领资料扫码、同行踩点 | 中（含位置） |
| 店铺访问 | 店铺ID、来源、时长、访问深度 | 低-中 | 误点、爬虫、同行比价 | 低 |
| 商品点击/详情浏览 | SKU（牌号+规格+产地+仓库）、次数、时长 | 中 | 看行情、随手翻 | 低 |
| 收藏 | SKU、时间 | **低-中**（钢贸中多为「记价格」书签，非购买意向） | 价格书签用途 | 低 |
| 资源/库存查看时长 | 资源单ID、停留秒数、滚动深度 | 中 | 挂着页面不看 | 低 |
| **筛选条件** | 牌号、规格区间、产地、仓库、计价方式 | **高**（筛选条件即需求画像，且是用户主动输入） | 低 | 中 |
| **报价单下载/导出** | 资源单、导出格式 | **高**（导出是为了内部报批/比价） | 低 | 低 |
| **求购单/找货单** | 完整交易要素 | **极高**（主动声明需求） | 低 | 中 |
| 议价/砍价记录 | 目标价、轮次 | 高 | 试探性砍价 | **高**（含价格底牌） |
| **IM 会话** | 文本、图片、文件、语音转写 | **极高但稀疏且高敏** | 微信分流、寒暄 | **极高**（通信秘密 + 商业秘密） |
| 下单/未支付/弃单 | 订单要素 | 极高 | — | 高 |
| 物流/过磅/提货查询 | 车次、磅单 | 高（复购前兆） | — | 中 |
| 账期/开票/资质申请 | 授信额度、票种 | **极高**（真实采购准备动作） | — | 高 |
| 行情资讯阅读 | 品类、区域 | 极低 | 泛阅读 | 低 |

**关键结论：意向价值最高的数据恰恰也是最敏感的数据（IM、议价、账期）。** 因此特征体系必须做**分域**：高敏数据只允许进入平台侧匹配模型和会话内 Copilot，不允许下沉为商家可见的画像字段（见文档 03「披露网关」）。

## 二、钢铁场景的信号强弱重排

### 2.1 强信号：交易要素齐备度（Deal-Readiness）

真正的采购意向体现为**交易要素的收敛**，而不是浏览次数。要素齐备度是本方案的第一主特征：

必备六要素：

1. **牌号/材质**：HRB400E、Q235B、Q355B、SPHC、SS400、45#、40Cr、304/201/316L
2. **规格**：螺纹 Φ12–40 / 卷板厚度与宽度（如 2.75×1250×C）/ 中板厚度 / 型钢型号（H型钢 200×100、工16、槽20）/ 管材（外径×壁厚）
3. **数量**：吨位（是否达到起订量、是否整车 30–35 吨、是否整垛）
4. **交货地与提货方式**：自提 / 送到（含卸车）/ 汽运火运水运、提货半径、仓库（如上海、乐从、无锡、唐山）
5. **时间**：本周 / 指定日期 / 长协月度分批
6. **计价与结算**：理计 or 过磅、含税 or 不含税、现款 / 月结 / 银承 / 电子承兑、锁价 or 点价

> 要素从 2 项收敛到 5–6 项的过程，就是意向从「看看」变成「要买」的过程。这比任何点击行为都可靠。

### 2.2 强信号：履约类提问（Fulfillment Questions）

这类问题只有真正要买的人才会问，是极高置信度的意向标志：

- 质量凭证：质保书 / 材质单 / 炉批号 / 探伤报告 / 复检
- 计量：过磅单、理计与过磅差、磅差如何处理、亏吨怎么算
- 票据资金：能不能开 13% 专票、承兑能不能收、贴息谁承担、账期几天、要不要预付
- 加工：定尺剪切、开平、纵剪、折弯、钻孔、除锈喷漆、代加工费与损耗
- 物流：几天到、能不能配车、运费多少、能不能卸车、进不进工地
- 资质：营业执照、项目备案、需不需要签框架合同

### 2.3 中信号

- 同一牌号规格**跨多个商家/多个产地反复比价**（说明在真实采购，而不是在看行情）
- 复访节奏：连续 2–3 天同一时段回访同类资源
- 报价单导出、资源单分享（分享意味着在给上级或客户报批）
- 从资讯页跳转到具体资源（阅读 → 行动的转化）

### 2.4 弱信号 / 反信号

- 纯资讯浏览、深夜泛浏览（多为从业者刷行情）
- 收藏后长期无动作（价格书签）
- 扫码后立刻退出
- 只看不筛选、不问规格（同行踩价的典型模式）
- **同行识别**：账号主体是钢贸商、只看价格不问交货、集中在早盘价格更新后 10 分钟内批量浏览 → 大概率是竞对采集价格，应识别并排除出线索池（否则销售会被喂一堆同行）

## 三、行情基线归一（本方案最重要的技术设计）

### 3.1 问题

钢价上行周期，全平台浏览量、询价量、收藏量会同步暴涨；下行周期集体萎缩。若直接用绝对行为量建模：

- 涨价周期：全平台意向分一起飘红 → 销售无法排序 → 功能失去意义
- 跌价周期：真实高意向客户被压到低分 → 漏掉真单
- 更糟的是模型会把宏观行情信号误学成个体意向

### 3.2 解法

**所有行为强度特征必须相对化，不使用绝对值：**

1. **同期分位归一**：对每个「品类 × 区域 × 时间窗」计算行为强度分布，用户特征取其在该分布中的分位数。
2. **行情因子作为分母/控制变量**：引入外部基准（螺纹钢期货主力合约、区域现货均价、当日调价幅度、库存与产量周数据），把行情驱动的部分显式剥离。
3. **同群对比（Peer Baseline）**：与「同类型买方 + 同区域 + 同品类」群体对比，而非与全平台对比。工地项目部和机械加工厂的行为模式完全不同。
4. **季节性去趋势**：北方冬季停工、雨季、春节前后备库、金九银十、月末冲量、季度末资金回笼，都需纳入日历特征。
5. **报价周期对齐**：以「早盘调价时刻」为一天的起点做时间对齐，而非自然日 0 点。

### 3.3 线索保鲜期

钢贸询价窗口极短，必须显式建模时效：

- 高意向线索**有效期默认 ≤ 24 小时**，超期自动降级并从工作台移除
- 「本周要货」类需求给 48–72 小时窗口
- 长协/框架类需求走独立的长周期跟进队列
- **不允许导出、囤积、二次分发线索**（既是合规要求，也是因为过期线索毫无价值）

## 四、特征分层设计

```
L0 原始事件（不可变，仅留存与审计）
        |
L1 会话内特征（仅本会话可见）
   · 规格要素抽取结果  · 提问类型分类  · 情绪/急迫度（仅用于平台侧质量监控，禁止披露给对手方）
        |
L2 店铺域特征（仅归属商家可见，聚合后）
   · 本店铺内浏览深度、要素齐备度、履约类提问数、比价轮次
        |
L3 平台域特征（仅平台侧匹配/风控使用，禁止下放到商家个体视图）
   · 跨商家比价宽度  · 采购节奏与复购周期  · 品类迁移  · 授信与账期画像
        |
L4 输出层（经披露网关裁剪后对外）
   · 意向等级（高/中/低）  · 需求要素摘要  · 建议动作  · 有效期
```

**分层的意义在于：权限模型可以直接绑定在层级上，而不是靠开发自觉。** L3 → 商家的任何链路在代码层面就应当不存在。

## 五、标签定义（Label）

单一「是否成交」标签在钢贸场景下过于稀疏且滞后（尤其是线下成交回填缺失），建议多任务：

| 标签 | 定义 | 用途 | 注意 |
|---|---|---|---|
| 有效沟通 | IM 中出现完整规格 + 数量，或双方交换要素 | 早期代理标签，密度高 | 易受平台内 IM 使用率偏差影响 |
| 询价成单率 | 询单 → 有效报价 → 确认 | 撮合效率主标签 | — |
| 平台内成交 | 订单支付/合同签署 | 主标签 | 稀疏 |
| 线下成交回填 | 商家在工作台标注「已成交」 | 补充标签 | 商家有动机少填（避佣金），需激励设计 |
| 长期价值 | 90 天内成交吨位/毛利 | 用于线索优先级排序 | — |

**必须避免的标签泄漏**：不要用「是否留了手机号」「是否加了微信」「是否被销售联系过」这类下游/干预后动作做特征去预测成交——线上会出现严重的因果倒置，模型上线即失效。凡是发生在「AI 输出线索之后」的动作，都不能进特征。

## 六、模型分层策略（不要一把 LLM 梭）

```
① 非结构化理解层（LLM / 小模型）
   输入：IM 文本、语音转写、采购清单图片/PDF/Excel
   输出：结构化要素 JSON（牌号、规格、数量、交货地、时间、计价、加工、提问类型）
   要求：抽取式而非生成式，字段级置信度，低置信走人工/追问；私有化或 VPC 内推理

② 规则引擎层（可解释、冷启动兜底、可运营配置）
   要素齐备度阈值 + 履约类提问命中 + 主动求购 → 直接判定高意向
   同行识别 / 爬虫 / 代扫码 → 直接排除
   ——上线第一版应以规则为主，规则能解决 70% 的排序需求，且销售看得懂、信得过

③ 统计模型层（LR / GBDT，如 LightGBM）
   输入：L2/L3 归一化特征 + 规则命中标记
   输出：内部意向概率（不对外展示原始分）
   要求：SHAP 可解释、按品类/区域分组校准（Isotonic/Platt）

④ 排序与配额层
   意向概率 × 商家承接能力（库存匹配度、历史响应速度、资质）× 反骚扰配额
   → 生成最终工作台队列
```

**为什么规则优先**：钢贸销售对黑盒极度不信任，而「因为他问了质保书和账期，还确认了 200 吨唐山提货」这种理由他立刻就认。可解释性在这个行业不是加分项，是准入条件。

## 七、数据质量治理要点

1. **主体归一（Entity Resolution）**：一人多号、一号多企业、业务员代注册。需以「企业主体 + 手机号 + 设备」做概率化归并，且**归并置信度低时不得生成个体线索**（避免张冠李戴造成真实商业损害）。
2. **规格标准化字典**：建立牌号/规格/仓库/区域的同义词与俗称词典（「四百螺」→ HRB400E、「二五」→ Φ25、「乐从」→ 佛山乐从仓、「理计」→ 理论计重），这是所有 NLP 环节的基础设施，值得单独投入。
3. **爬虫与同行流量识别**：早盘价格更新后的批量访问模式、无筛选纯翻页、UA/IP 聚集特征。
4. **埋点契约**：事件 schema 版本化，禁止在埋点里塞明文敏感字段（手机号、合同金额）。
5. **时区与时间戳统一**：全链路 UTC 存储 + 业务时区展示，避免早盘对齐算错。
6. **样本偏差监控**：平台内 IM 使用率、授权开启率随时间变化会导致特征分布漂移，需按周监控 PSI。

## 八、给买方的「对价」也需要数据支撑

授权制要成立，买方必须真的拿到好处。以下能力依赖同一套数据资产，应与意向分析同批建设：

- **智能找货 / 凑单**：跨仓库、跨商家凑齐规格与吨位，解决「差 20 吨凑不齐一车」
- **价格提醒与点价建议**：目标规格跌到目标价提醒，结合盘面升贴水
- **匿名代询价**：平台代为向多家询价，买方身份不暴露
- **质检与磅单核验、物流拼车、账期资格预审**

这些功能对买方是纯收益，是换取授权最有说服力的筹码——**没有它们，「请开启意向共享」就是一句纯索取的话，没人会点。**
