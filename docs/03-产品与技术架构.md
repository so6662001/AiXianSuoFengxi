# 产品与技术架构设计

> 架构的唯一目标：**让「侵犯买方信任」在技术上不可能发生**，而不是依赖流程约束和人的自觉。

## 二、披露网关（Disclosure Gateway）详细设计

这是整个方案的安全核心。**任何 AI 结果到达商家之前，必须且只能经过此网关；不存在绕过路径（数据库直连、报表工具、导出任务均需走网关或被禁止）。**

### 2.1 职责

| 能力 | 实现要点 |
|---|---|
| 授权校验 | 每次读取都实时校验买方授权状态（开启/撤回/过期）+ 勿扰名单，撤回后缓存立即失效 |
| 域隔离 | 请求上下文强制携带 `merchant_id`，查询层强制注入店铺域过滤；L3 平台域特征在 DTO 层不存在对应字段 |
| 字段白名单 | 出站字段以白名单声明（配置化 + 代码评审双控），新增字段需走隐私评审流程 |
| 分级化 | 原始概率 → 等级映射，映射表由平台控制，商家不可见分值与阈值 |
| k-匿名 | 聚合看板中任一维度组合下用户数 < k（建议 k=5）时返回「样本不足」 |
| 配额与限流 | 单个买方单日被联系上限、同一线索最多分发给 N 家（建议 N ≤ 3）、静默期 |
| 有效期 | 线索 TTL（默认 24h），过期自动下架，禁止导出 |
| 审计 | 不可篡改日志（追加写 + 定期归档），留存 ≥ 6 个月，支持按买方视角自查「谁看过我的什么」 |

### 2.2 出站字段白名单（示例）

允许：

```json
{
  "lead_id": "ld_xxx",
  "intent_level": "high",              // 仅 high/medium/low
  "demand": {
    "grade": "HRB400E",
    "spec": "Φ25",
    "quantity_ton": 200,
    "delivery": { "mode": "self_pickup", "area": "唐山" },
    "need_by": "2026-08-21",
    "settlement": "过磅/含税/月结30天",
    "processing": null
  },
  "matched_sku": ["sku_123"],
  "suggested_action": "按当前唐山均价给出含税送到价，并主动提供质保书样本",
  "expires_at": "2026-08-18T02:00:00Z",
  "contact": null                       // 仅在买方单独同意后填充
}
```

禁止出站（技术层面不提供该字段）：

- 任何行为轨迹时间线、停留秒数、点击序列
- 跨商家浏览/比价对象、比价家数
- IM 原文、原文摘要、情绪标签
- 「紧迫度」「价格承受力」「可接受涨幅」等议价底牌类推断
- 原始意向分、模型特征值
- 未经单独同意的联系方式、企业主体名称

### 2.3 买方侧透明面板（合规与信任的关键抓手）

买方可在「我的隐私」中看到：

- 当前授权状态与授权范围（分商家、分品类可控）
- **谁在什么时候看过我的什么信息**（读取审计对买方开放，这是建立信任最有效的动作）
- 一键撤回授权、一键勿扰、一键关闭个性化推荐（个保法第 24 条要求的「便捷拒绝方式」）
- 意向判定依据说明（可解释性输出，对应第 24 条「要求说明」的权利）

> 把审计日志反向开放给买方，是最低成本、最高收益的信任设计：它让「平台不会滥用」从承诺变成可验证的事实。

## 三、IM 数据的处理架构（最高敏感度）

**原则：会话域封闭，结果不出会话。**

1. **独立存储与密钥**：会话库与业务库物理隔离，消息内容字段级加密，密钥由 KMS 管理并与业务库密钥分离；DBA 无明文读取权限。
2. **推理不出域**：要素抽取使用私有化部署模型或 VPC 内推理端点；**禁止调用境外/公共大模型 API**（既是数据出境合规问题，也涉及商业秘密）。
3. **输出裁剪**：会话 AI 只向意向引擎输出**结构化要素**（牌号、规格、数量、交货地、时间、提问类型），**不输出原文、不输出摘要、不输出情绪**。
4. **双边可见性对称**：会话内 Copilot 的能力（规格清单整理、报价单生成、要素缺失提示、合同风险提示）应对买卖双方同时开放。**单边赋能会被立刻感知为偏袒。**
5. **明确的用户告知**：会话内首次触发 AI 辅助时给出可见提示与关闭入口，不做静默分析。
6. **留存最小化**：抽取后的中间产物按需清理，原文留存周期遵循法定与举证需要，不为「训练」目的无限期留存（如需用于训练，须单独同意 + 去标识化）。

## 四、卖方工作台的产品形态

### 4.1 首页：今日待办（而非客户名单）

```
今日高意向询单（3）                              有效期倒计时
─────────────────────────────────────────────────────────
① 螺纹钢 HRB400E Φ25 · 200吨 · 唐山自提 · 本周内
   过磅含税 · 月结30天 · 需质保书
   ▸ 你的可匹配库存：唐山XX仓 Φ25 现货 480吨
   ▸ 建议：报含税自提价，附质保书样本，说明可当日装车
   [ 一键报价 ]   [ 转人工跟进 ]        剩余 18 小时
```

**注意这个界面里没有客户名字、没有手机号、没有浏览轨迹。** 卖方拿到的是「一个可执行的商机」，而不是「一个可以骚扰的人」。买方在收到报价后决定是否揭示身份并进入 IM。

### 4.2 店铺经营诊断（纯自家聚合数据，零隐私风险）

- 曝光/询价/成交漏斗，按牌号规格拆解
- 「你的 Φ20 螺纹曝光排名前 20%，但询价转化低于同区域均值，报价高出区域均价约 30 元/吨」
- 响应时长排名与流失归因（首响超过 X 分钟的询单流失率显著上升）
- 库存周转与滞销预警（结合行情，提示余材/非标定尺消化建议）

这个模块建议**第一个上线**：价值明确、商家爱看、完全不触碰买方隐私，可以先把数据管道、指标体系、商家使用习惯全部跑通。

### 4.3 响应 SLA 与线索质量闭环

- 首响时长纳入商家评分，影响后续线索分发优先级（**这是抑制骚扰、激励认真报价的核心杠杆**）
- 商家对每条线索反馈「准/不准/已成交」，形成模型的在线学习信号
- 滥用行为（导出、频繁跳过、被投诉）直接降低分发权重

## 五、模型服务与工程要点

| 项 | 建议 |
|---|---|
| 抽取模型 | 私有化中小参数 LLM + 领域词典约束解码；输出 JSON Schema 校验，字段级置信度，低置信不落库 |
| 排序模型 | LightGBM，按「品类×区域」分组训练或加分组特征；概率校准（Isotonic） |
| 特征存储 | 在线 Redis（实时行为窗口）+ 离线 Hive/Doris；**训练/服务特征同源**，避免线上线下不一致 |
| 行情基准接入 | 期货主力合约、区域现货均价、社库厂库周数据；缺失时降级为同期分位归一 |
| 可解释性 | 每条线索附「判定依据」（命中的要素与提问），SHAP 用于内部分析 |
| 实时性 | 线索生成端到端目标 < 1 分钟（钢贸询价窗口短，延迟等于失效） |
| 监控 | 特征 PSI、等级分布漂移、精准度反馈率、网关拦截统计、越权尝试告警 |
| 灰度 | 按品类（先螺纹/热卷）× 区域 × 商家白名单三重灰度，配比可动态调整 |
| 回滚 | 规则与模型分离部署，模型异常时可秒级降级为纯规则 |

## 六、权限与安全

- **RBAC + 数据域双控**：角色决定能调什么接口，数据域决定能看到哪些行的数据；两者独立校验。
- **内部运营查询留痕**：运营查看用户明细需填写事由并留痕，高频访问触发告警。
- **禁止导出**：线索页禁止批量导出/复制/截图水印（截图水印含操作人 ID，用于泄漏溯源）。
- **商家协议约束（DPA）**：商家作为独立处理者，明确禁止转售线索、禁止用于差别定价、禁止用于平台外营销，违约条款可执行（保证金/降权/清退）。
- **开放 API 同等约束**：ERP 对接接口必须走同一披露网关，不得开后门。

## 七、需要显式设计的「不做」

架构评审时应逐条确认以下路径**在代码层面不存在**，而非「暂时没做」：

- [ ] 卖方工作台不存在任何返回 L3 平台域特征的接口
- [ ] 不存在任何返回 IM 原文/摘要给非会话参与方的接口
- [ ] 不存在返回原始意向分的字段
- [ ] 不存在「紧迫度」「价格承受力」类字段
- [ ] 不存在绕过网关的报表/BI/数据库直连给商家的通路
- [ ] 不存在线索批量导出接口
- [ ] 不存在向境外/公共大模型 API 发送会话内容或客户名单的调用
