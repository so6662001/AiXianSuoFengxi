# 合规与红线清单

> 说明：以下为工程与产品落地视角的合规梳理，法律条款解读以最终法务/外部律师意见为准。
> 建设原则：合规能力（授权、审计、拒绝权、境内推理）必须在**第一版**进入架构，事后补建的成本与风险远高于一开始就做。

---

## 一、条款映射与产品化落地

### 1.1 《个人信息保护法》

| 条款 | 要求 | 产品化落地 |
|---|---|---|
| 第 5、6 条 | 合法、正当、必要、诚信；最小必要 | 特征清单逐项论证必要性，删除「有就采」的字段；埋点评审制 |
| 第 13、14 条 | 取得同意，充分告知 | 独立的《AI 意向分析与数据使用说明》，用大白话讲清「采什么、给谁、用来干什么、能得到什么」 |
| 第 15 条 | 撤回同意的便捷方式 | 隐私中心一键撤回，撤回后线索**立即**失效（含缓存），不留延迟 |
| 第 16 条 | 不得因拒绝而拒绝提供服务 | **拒绝授权的买方必须能正常浏览、询价、下单**，只是不进入定向线索池 |
| 第 17 条 | 告知处理目的、方式、种类、保存期限 | 隐私政策 + 授权弹窗双层告知 |
| 第 23 条 | 向他人提供个人信息需**单独同意** | 「向商家提供联系方式」必须是独立勾选项，不得与注册协议捆绑 |
| 第 24 条 | 自动化决策须透明公平；不得在交易价格上不合理差别待遇；营销须提供不针对个人特征的选项或便捷拒绝；重大影响决定可要求说明并拒绝 | ① 禁止意向分参与定价（协议 + 技术监测）；② 提供「关闭个性化」开关；③ 提供判定依据说明；④ 提供拒绝自动化线索的入口 |
| 第 44–47 条 | 知情权、决定权、查阅复制权、删除权 | 隐私中心提供「我的数据副本导出」「删除申请」，并对买方开放**读取审计日志**（谁看过我什么） |
| 第 51 条 | 安全管理制度、加密去标识化、权限管理、培训、应急预案 | 见文档 03 权限与安全章节；销售端使用规范培训与考核 |
| 第 55、56 条 | 自动化决策、对外提供、处理敏感信息前须做 **PIA** 并留存 3 年 | 上线前完成 PIA 报告；每次披露口径变更重新评估 |

### 1.2 其他法规

| 法规 | 要点 | 落地 |
|---|---|---|
| 《数据安全法》 | 分类分级、重要数据识别、风险监测 | 建立数据分级表（L0 公开 / L1 内部 / L2 敏感 / L3 高敏：IM、议价、授信） |
| 《网络安全法》 | 日志留存 ≥ 6 个月、等保 | 审计日志 ≥ 6 个月（建议 12 个月），追加写不可篡改 |
| 数据出境相关规定 | 调用境外模型 API 构成出境 | **模型推理全部境内**，私有化或 VPC 内部署，禁用公共大模型 API 处理会话与客户数据 |
| 《电子商务法》第 18 条 | 提供不针对个人特征的搜索结果选项 | 商品/资源列表提供「默认排序」（价格/距离/时间），不默认强制个性化 |
| 《反不正当竞争法》第 9 条 | 商业秘密保护 | 买方采购计划、下游客户信息、成交价均按商业秘密对待，不跨主体披露 |
| 反垄断相关规定 | 避免便利横向价格协同、数据驱动价格歧视 | 不向多个卖方同时披露同一买方的价格敏感信息；不向卖方披露其他卖方的具体报价（盲报价） |
| 《民法典》人格权编 | 私密信息、通信自由 | IM 内容按通信秘密处理，非会话参与方绝不可见 |

## 二、红线清单（不可触碰）

技术评审与上线评审必须逐条核对：

1. ❌ **不向商家展示跨商家行为**：客户在其他店铺看了什么、比了几家、看了谁的货，一律不可见。
2. ❌ **不向商家展示个体行为轨迹与停留时长**。
3. ❌ **不把 IM 内容用于商家侧画像或跨店定价**；分析结果只回本会话。
4. ❌ **不输出议价底牌类字段**：紧迫度、价格承受力、可接受涨幅、预算上限。
5. ❌ **未经单独同意不提供联系方式**。
6. ❌ **不按线索条数计费**（商业模式层面的红线，见第四节）。
7. ❌ **不允许线索导出、囤积、二次分发**。
8. ❌ **不向境外或公共大模型 API 发送会话内容、客户名单、成交数据**。
9. ❌ **不做静默分析**：任何 AI 介入都有可见提示与关闭入口。
10. ❌ **不以拒绝授权为由降低基础服务质量**。
11. ❌ **不允许意向等级影响同一资源对不同买方的展示价格**。
12. ❌ **主体归并置信度不足时不生成个体线索**（防张冠李戴造成真实商业损害）。

## 三、告知与授权的话术设计

合规文本写得像法律免责声明，用户只会直接同意然后心里犯疑；写成价值交换，才既合规又建立信任。

**反面示例（会引发顾忌）**：

> 「我们将收集您的浏览、点击、收藏、聊天等行为数据，用于用户画像与精准营销，并可能提供给平台内商家。」

**正面示例（同样合规，但用户看得懂且愿意点）**：

> **让好货主动找到你**
>
> 开启后，你在平台发布的采购需求（牌号、规格、吨位、交货地、时间）会**匿名**发给匹配的货源方，他们直接给你报价。
>
> · 我们**不会**把你的公司名称、联系方式、浏览记录告诉任何商家，除非你选中报价后自己决定联系
> · 我们**不会**把你的比价情况告诉商家，报价方之间也互相看不到对方的价格
> · 你可以随时关闭，也可以随时查看「谁看过我的什么信息」
>
> 开启后你将获得：多家限时比价 · 优先货源 · 免费质保书核验 · 物流拼车
>
> [ 开启 ]  [ 暂不开启（不影响正常浏览与下单） ]

单独同意项（默认不勾选）：

> ☐ 允许我选中的商家在报价后直接与我电话联系

## 四、商业模式的合规与伦理约束

**按线索条数收费 = 产品必然滑向侵入式。** 原因是机制性的：收入与线索产量正相关后，团队的每一次迭代都会倾向于放宽披露口径、降低意向阈值、增加分发家数。这不是靠价值观能守住的，必须靠商业模式设计规避。

推荐的收费结构：

| 模式 | 说明 | 激励方向 |
|---|---|---|
| SaaS 订阅 | 经营诊断 + 报价 Copilot + 响应管理工具 | 卖工具价值，与隐私无关 ✅ |
| 按成交抽佣/服务费 | 撮合成功后收费 | 与买卖双方利益一致 ✅ |
| 按有效响应计费 | 商家提交有效报价后计费（买方评价有效性） | 激励认真报价而非广撒网 ✅ |
| 按线索条数计费 | 拿到多少条线索付多少钱 | 激励多产线索 → 侵入式 ❌ |
| 按联系方式解锁计费 | 解锁手机号付费 | 本质是卖用户信息 ❌❌ |

## 五、上线前合规检查清单

- [ ] PIA（个人信息保护影响评估）完成并归档
- [ ] 隐私政策 / AI 使用说明更新并完成用户告知
- [ ] 单独同意项独立呈现、默认不勾选、可撤回
- [ ] 拒绝授权路径的服务完整性回归测试通过
- [ ] 披露网关字段白名单经隐私评审签署
- [ ] 出站字段扫描：确认无轨迹、无原文、无原始分、无议价底牌字段
- [ ] 跨商家域隔离渗透测试（尝试通过参数篡改获取其他店铺数据）
- [ ] 审计日志完整性验证 + 买方自查页面可用
- [ ] 模型推理链路网络出口审计（确认无境外调用）
- [ ] 商家协议 / DPA 补充条款生效，含禁止转售、禁止差别定价、违约处置
- [ ] 反骚扰配额生效并可实时调整
- [ ] 数据删除/导出流程可用并有 SLA
- [ ] 销售端使用规范培训与考试完成
